# TASK-019 — Automated tests

**Item:** [`agile/items/TASK-019-resume-session.md`](../items/TASK-019-resume-session.md)
**File:** `src/lib/session.test.ts`.

## What the tests are shaped like, and why

The port records every call it receives, in order, and the assertions are on
that list. This is the point of the item rather than a stylistic choice: the
defect that got through was *a call that never happened*, and a test that
checked a return value would have passed against the broken shell exactly as the
suite did.

```ts
const { port, calls } = recorder({ active: '/tmp/last-session' });
await resumeSession(port);
expect(calls).toContain('open /tmp/last-session');
```

## `src/lib/session.test.ts` — 13 assertions, unit

No document, no stores, no Tauri. `recorder()` builds a `ResumePort` from a few
overrides and appends a line per call.

| Group | What it holds | Why it can be wrong without anyone noticing |
| --- | --- | --- |
| a path on the command line | it wins outright: `launchPath`, then `open`, and nothing else | a launch that also reopened the last tab would open two repositories and land on the wrong one |
| a path on the command line | no `goto` and no `want`, even when a place is stored for that path | the command line is a request for a repository, not for the screen somebody left it on |
| the last session | the active tab is opened | this is the missing call itself: the strip is restored from storage by `workspace.init()`, and without this the name across the top is a label on an empty session |
| the last session | the whole order — `launchPath`, `active`, `placeOf`, `open`, `goto`, `want` | asserted as one list, so a step that moves is a failure rather than a silent reordering |
| the last session | `placeOf` is read **before** `open` | opening a repository can move the active tab, and a place read afterwards would be the new tab's |
| the last session | no `goto` when the stored route is the one already on screen | navigating to where you already are re-runs a screen's load for nothing |
| the last session | no `want` when the tab had no commit selected | `graph.want(null)` would hold the walk open for an id that does not exist |
| the last session | a tab with no stored place is still opened | the place is a convenience; the repository is the point |
| a tab that no longer resolves | the sequence stops after the failed `open` | navigating into a screen for a repository that is not open is the blank-window class of bug |
| a shell torn down | nothing runs after the first cancellation check | the shell can unmount while the launch path is still being read |
| a shell torn down | no `open` when it went away during the path read | an open that lands after teardown writes into a store nobody is watching |
| a shell torn down | no `goto` when it went away during the open | a navigation after teardown is the one with a visible symptom |

## What is not tested here, and why

That the real port is wired correctly. `resumeSession` is asserted against a
recorder, so a shell that passed `workspace.placeOf` where it meant
`workspace.active` would satisfy every test here. Two things stand against that:
`ResumePort` is typed, so a missing or mistyped member fails `npm run check`;
and the sweep launches the application four ways by hand, which is the only
place the real wiring is exercised.
