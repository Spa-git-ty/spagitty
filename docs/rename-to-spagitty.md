# Renaming the project to Spagitty

The project is being renamed **GitLumiere → Spagitty**. This document is the
work order for that rename and the map of every place the old name lives.
It follows the shape of TASK-004, which renamed GitLord to GitLumiere; read
that item (`agile/items/TASK-004-rename-to-spagitty.md`) first — this is the
same operation with a new pair of names.

A name in a Tauri project is not a string in one file: crate names, the bundle
identifier, persisted keys and every document all carry it. Leaving any behind
means two names in one product.

## The name mapping

Every occurrence is one of these forms. Replace mechanically, preserving case
position:

| Old | New |
| --- | --- |
| `GitLumiere` | `Spagitty` |
| `gitlumiere` | `spagitty` |
| `GITLUMIERE` / `GIT_LUMIERE` | `SPAGITTY` / `SPAGITTY` (check context) |
| `gitlumiere-core` / `gitlumiere_core` | `spagitty-core` / `spagitty_core` |
| `gitlumiere_lib` | `spagitty_lib` |
| `dev.gitlumiere.app` | `dev.spagitty.app` (see decision D1) |

Search with case-insensitive matching so no variant escapes:
`rg -i lumiere`. The same for the old-old name: `rg -i "\blord\b"`.

## Decisions to make before starting

**D1 — Bundle identifier.** `dev.gitlumiere.app` becomes a new identifier.
Suggested: `dev.spagitty.app`. Any value works as long as product name,
identifier and capability manifest agree — a mismatch makes the OS treat it as
a different application.

**D2 — History prose in `agile/`.** Precedent (TASK-004) is that records are
renamed too: `agile/` is living documentation, not an archive, and Amendment 11
makes stale docs defects. Rename every mention there, *except* where the old
name is the subject of the sentence describing the rename itself — TASK-004
must keep saying "from GitLord to GitLumiere" or it stops describing what
happened. Add TASK-004's title a second reading: it stays as is, and this
document takes over as the current record.

**D3 — `design_handoff_gitlord/` stays.** It kept its name through the last
rename because it is a historical artifact of the design handoff. Same call
now. Do not touch anything under it.

## Structural changes (not find-and-replace)

These need moves and edits, not string substitution:

1. **Crate directory**: `crates/gitlumiere-core/` → `crates/spagitty-core/`.
   Then update `crates/spagitty-core/Cargo.toml` (`name`) and the workspace
   `Cargo.toml` (`members`, `workspace.dependencies`, `repository`).
2. **`src-tauri/Cargo.toml`**: package `name = "spagitty"`,
   `default-run = "spagitty"`, lib `name = "spagitty_lib"`, and the dependency
   key `spagitty-core`.
3. **`src-tauri/src/lib.rs`**: the `gitlumiere_lib` macro invocation becomes
   `spagitty_lib`; the module doc comment naming `gitlumiere-core`.
4. **`src-tauri/tauri.conf.json`**: `productName: "Spagitty"`,
   `identifier` per D1, window `title: "Spagitty"`.
5. **`package.json`**: `"name": "spagitty"`.

## Generated files — never hand-edit

- `Cargo.lock` — regenerated by the first `cargo build` after the rename.
- `package-lock.json` — regenerated by `npm install`.
- `src-tauri/gen/schemas/*` — regenerated by the Tauri build; verify the
  identifier propagated rather than editing them.

If the diff shows hand-edits to any of these, something went wrong.

## Persisted keys (localStorage)

Every prefix changes, with **no migration shim** — pre-release, no shipped
users, same reasoning as TASK-004's non-scope. Anyone running a dev build loses
zoom, text size, theme, recents and panel layout once. Inventory found today:

```
gitlumiere.scale.zoom      gitlumiere.scale.text     gitlumiere.panels
gitlumiere.theme.family    gitlumiere.theme          gitlumiere.workspace
gitlumiere.diff            gitlumiere.graph.columns  gitlumiere.graph.visibility
```

Plus the settings/recents keys in `src-tauri/src/settings.rs` and
`recents.rs`, which live beside the repository list in the config directory —
grep those two files for the prefix rather than trusting this list.

## Thread and event names

`src-tauri/src/graph_worker.rs`, `search_worker.rs`, `clone_worker.rs` carry
thread names `gitlumiere-watch`, `gitlumiere-search`, `gitlumiere-clone`.
Rename for consistency; nothing external depends on them.

## User-facing strings

- Title bar (`src/lib/chrome/TitleBar.svelte`) and About
  (`src/lib/settings/LicenseSection.svelte`, `src-tauri/src/about.rs`).
- Notices and dialogs that speak the app's name.
- `NOTICE` (trademark/attribution text), `deny.toml` annotations.
- Icons: `tools/make-icons.py` references the name; regenerate icons after.

## Prose sweep

Case-insensitive replace across: `README.md`, `CONTRIBUTING.md`, everything
under `docs/` (including this file's siblings and `docs/reference/`),
everything under `agile/` (per D2), `.github/workflows/gates.yml`,
`prerelease.yml`, `.github/actions/linux-deps/action.yml`.

Watch for these traps during the prose sweep:

- `docs/reference/gitkraken-commit-graph.md` mentions **GitKraken**, not the
  project name — leave those alone. Only its references to GitLumiere change.
- Sentence-start occurrences need `Spagitty` capitalised; mid-sentence brand
  mentions stay `Spagitty` anyway, but code identifiers must stay lowercase.
- The word "lumière" could theoretically appear in French text — there is
  none today, but check `rg -i lumiere` hits before bulk-replacing.

## Order of operations

1. Make decisions D1–D3.
2. Structural changes (crate dir, manifests, tauri.conf.json).
3. Run `cargo build` once so `Cargo.lock` regenerates; run `npm install` for
   the lockfile.
4. Code sweep: `rg -il lumiere` over `src/`, `src-tauri/src/`,
   `crates/spagitty-core/` — every hit gets replaced by hand (tests assert on
   strings; blind sed has broken them before).
5. Prose sweep per above.
6. Full verification below.
7. One commit for the whole rename — TASK-004 landed as a single commit and
   partial renames are how two-name products happen. Suggested branch:
   `task/rename-to-spagitty`, following the stacking convention until a
   remote exists.

## Acceptance criteria

- `rg -i lumiere` over the working tree excluding `.git`, `node_modules`,
  `target`, `.svelte-kit`, `build`, `coverage` returns only this document and
  `agile/items/TASK-004-rename-to-spagitty.md`.
- `cargo build`, `cargo test --workspace`, `npm run check`, and `npm test`
  all pass against the renamed crate.
- `productName`, the bundle identifier, and the capability manifest agree.
- Nothing under `design_handoff_gitlord/` changed.

## Explicitly out of scope

- The repository directory on disk (`~/dev/foss/gitlumiere`) and any remote
  path. Neither affects the built product; move them when convenient.
- Migrating users' persisted state (see above).
- Domain registration, crates.io/npm squating, trademark checks — recorded as
  follow-ups, not part of this rename.

## Outcome

The rename landed on `task/rename-to-spagitty`.

**Decisions taken.** D1: the bundle identifier is `dev.spagitty.app`, matching
`productName: "Spagitty"` and the capability manifest. D2: `agile/` was swept
with no exception — see the amendment below. D3: `design_handoff_gitlord/` was
not touched.

**Amendment to D2 — the TASK-004 records were swept too.** The plan above
carved out TASK-004 so it would keep saying "from GitLord to GitLumiere". That
exception was dropped: `agile/items/TASK-004-rename-to-spagitty.md` (renamed
from `-gitlumiere.md`), `agile/plans/TASK-004-plan.md`,
`agile/testing/TASK-004-sweep.md` and `agile/README.md`'s index row now all
name Spagitty. The consequence is that TASK-004 reads as renaming GitLord to
Spagitty, which is not what happened in that commit; this document is the only
record that the intermediate name existed at all. That is the trade the
one-name rule asks for, and it was made deliberately.

**Other deviations from the plan above.**

1. *One quoted error message in CI stays.* `.github/workflows/gates.yml:153`
   quotes gitleaks-action verbatim: `"[GitLumiere] is an organization. License
   key is required."` That is the GitHub account's name, and the account has
   not been renamed. Rewriting the quote would fabricate it. Revisit when the
   GitHub organization is renamed.
2. *The `git-foo` naming note was deleted, not renamed.* `README.md` and
   `src-tauri/src/main.rs` both explained why the binary is `gitlumiere` and
   never `git-lumiere`: git treats any `git-foo` on `PATH` as a subcommand.
   `spagitty` does not begin with `git-`, so the hazard is gone and the note
   would have renamed into nonsense.
3. *Resolved.* The workspace `repository` URL points at
   `github.com/Spa-git-ty/spagitty`, which is where the project lives and where
   its releases are published. It named `github.com/spagitty/spagitty` — nobody's
   — from the rename until the first public release, when it was made true.

   The original note read: *"The workspace `repository` URL now points at
   `github.com/spagitty/spagitty`, which does not exist yet. The git remote is
   unchanged (`github.com/GitLumiere/gitlumiere`), per the out-of-scope note
   above. The manifest field and the remote disagree until the GitHub side
   moves."* The GitHub side has now moved, and they agree.

**The icon was redrawn, not just renamed.** `tools/make-icons.py` previously
drew a commit lane with a branch elbow — a mark that said nothing about the new
name. It now draws three strands that begin tangled above the frame and
straighten into parallel commit lanes, each capped by a commit node: spaghetti
above, a commit graph below. The strokes are stamped discs rather than
`ImageDraw.line` with `joint="curve"`, which left seams that showed as hatching
once the image was scaled down. Every file in `src-tauri/icons/` was
regenerated.

**A test failure that came with the environment, fixed here.** `npm test` was
failing 21 tests in `src/lib/scale.test.ts` before this branch started. Node 22
added its own `localStorage` global, `undefined` unless the process was started
with `--localstorage-file`, and it shadows the one happy-dom installs on the
window. The bare `localStorage` every store uses — correct inside a webview —
therefore resolved to nothing under test, so each persistence path silently took
its catch branch, and the one test file that used storage without stubbing it
first failed outright. `vitest.setup.ts` now installs one happy-dom `Storage`
instance on both `globalThis` and `window`; `vi.stubGlobal` in the sibling test
files still overrides it.

**Verification.** `cargo build --workspace`, `cargo test --workspace`
(282 passed), `npm run check` (0 errors) and `npm test` (1367 passed, 56 files)
all pass against the renamed crate. `Cargo.lock`, `package-lock.json` and
`src-tauri/gen/schemas/` were regenerated, not hand-edited; the generated
capability schema carries `Spagitty`.

`rg -i lumiere` over the working tree now returns this document and the quoted
CI error, and nothing else.
